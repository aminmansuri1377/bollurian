# قفل مدیریت قیمت مادر

مبنای patch: `9cb48439818b2f38f4c09050449c0d61437b5012`، کامیت `10 stop`.

## رفتار جدید

رمز آزمایشی `1111` است. ارقام فارسی و عربیِ همین رمز نیز پذیرفته می‌شوند.
هر بار ورود به مدیریت قیمت مادر نیازمند رمز است. جدول مدیریت پیش از تأیید رمز اصلاً mount نمی‌شود.
با بستن پنجره، آخرین تغییرات ذخیره می‌شوند و سپس دسترسی باطل می‌شود.
بازنشانی قیمت‌های نمونه هم رمز می‌خواهد؛ پس از ورود، همان تأیید، پشتیبان و تابع بازنشانی قبلی اجرا می‌شود.

پنج رمز اشتباه پیاپی، ورود را در همان اجرای برنامه برای ۶۰ ثانیه متوقف می‌کند.
نشست فقط در حافظه است و در SQLite، localStorage یا فایل پشتیبان ذخیره نمی‌شود.

## چیزی که تغییر نکرده است

فایل‌های محاسبات، جدول‌های تعداد، انتخاب برند، نوع پکیج، ظرفیت، موتور، ریل و کاتالوگ ویرایش نشده‌اند.
توقف‌های ۳ تا ۱۰، تفاوت ظرفیت‌ها و ادغام پیچ‌های ریل T9 و T16 همان قوانین فعلی پروژه‌اند.
قالب PDF، قیمت‌های موجود، انتخاب‌های ذخیره‌شده، نام و تلفن مشتری و دیتابیس قبلی حفظ می‌شوند.
هیچ بازنشانی خودکار، مهاجرت داده یا تغییر واحد پولی وجود ندارد.

تنها تفاوت مسیر ذخیره‌سازی: تغییر `prices` یا `previousPrices` در نسخه Tauri به نشست معتبر مدیر نیاز دارد.
تغییر مشخصات پیش‌فاکتور، توقف، ظرفیت، برند و ریل، با قیمت‌های مادر دست‌نخورده، همچنان بدون رمز ذخیره می‌شود.
مقادیر نامعتبر قیمت پیش از ذخیره رد می‌شوند؛ قیمت صفر همچنان معتبر است.
خروجی محاسبات و ساختار payload پیش‌فاکتور تغییر نکرده است.

## چرا رمز داخل NEXT_PUBLIC یا کد رابط نیست؟

برنامه با خروجی استاتیک Next.js اجرا می‌شود، نه با یک سرور Node.js مخفی.
متغیر `NEXT_PUBLIC_...` به کد مرورگر وارد می‌شود و محل نگهداری رمز محرمانه نیست.

در نسخه نصب‌شده:
- فایل `src-tauri/admin-password.json` فقط verifier نمک‌دار PBKDF2-SHA256 با ۶۰۰٬۰۰۰ تکرار دارد.
- Rust رمز را بررسی می‌کند و یک توکن تصادفی ۲۵۶ بیتی می‌سازد.
- کنترل رمز روی worker انجام می‌شود تا کار مشتق‌سازی رمز، thread اصلی پنجره را مسدود نکند.
- فرمان `save_state` در یک تراکنش، قیمت‌های قبلی و جدید را مقایسه می‌کند و تغییر بدون مجوز را رد می‌کند.
- هنگام بستن مدیریت، ابتدا صف ذخیره کامل و سپس نشست باطل می‌شود.

این قابلیت رمزگذاری دیتابیس نیست. قیمت برای محاسبه پیش‌فاکتور باید خوانده شود و در صفحه اصلی هم نمایش دارد.
فردی که اختیار کامل فایل SQLite، فایل اجرایی یا سیستم‌عامل را دارد می‌تواند از بیرون برنامه داده یا برنامه را دستکاری کند.
محدودیت تلاش با بسته‌شدن کامل برنامه از نو شروع می‌شود.
رمز `1111` فقط برای تست است؛ قبل از تحویل واقعی آن را تغییر دهید.

## تغییر رمز قبل از ساخت نسخه مشتری

در ترمینال ریشه پروژه:

```powershell
npm run admin:password
```

رمز جدید را دو بار وارد کنید؛ کاراکترها در ترمینال نمایش داده نمی‌شوند.
خود رمز به فایل یا تاریخچه آرگومان‌های فرمان نوشته نمی‌شود؛ فقط verifier به‌روز می‌شود.
برای مصرف واقعی یک رمز طولانی و غیرقابل حدس انتخاب کنید؛ حداقل ۱۲ کاراکتر توصیه می‌شود.
پس از تغییر verifier باید برنامه مجدداً build و نسخه جدید نصب شود:

```powershell
npm run desktop:build
```

ویرایش این فایل روی سیستم توسعه، رمز نسخه‌ای را که قبلاً روی سیستم مشتری نصب شده، از راه دور عوض نمی‌کند.
در این patch صفحه تغییر رمز در زمان اجرای برنامه اضافه نشده است.

## رفتار نسخه مرورگر

`npm run dev` بدون Tauri فقط پیش‌نمایش توسعه است. برای حفظ امکان تست UI، بررسی رمز با WebCrypto انجام می‌شود
و یک هشدار واضح درباره آزمایشی‌بودن قفل نمایش داده می‌شود.
این حالت مرز امنیتی نیست؛ کسی که DevTools دارد می‌تواند رابط توسعه را دستکاری کند.

در خروجی production وب که بیرون از Tauri باز شده، مدیریت قیمت fail-closed است؛ از نسخه نصب‌شده استفاده کنید.
خطای تأیید رمز در محیط Tauri هرگز به تأیید ساده مرورگر fallback نمی‌کند.
قفل واقعی را با `npm run desktop:dev` و سپس با نصب‌کننده ویندوز آزمایش کنید.

## اعمال و آزمون

ابتدا تغییرات فعلی خود را commit یا stash و فایل patch را کنار `package.json` قرار دهید.

```powershell
git apply --check .\bollurian-admin-access.patch
git apply .\bollurian-admin-access.patch

npm run test:admin
npm test
npm run typecheck
npm run desktop:dev
```

اگر `--check` خطا داشت، patch را به اجبار اعمال نکنید؛ نسخه فایل‌ها متفاوت است.
وابستگی npm جدید نداریم. سه dependency مستقیم Rust اضافه شده‌اند:
`serde_json`، `pbkdf2` و `rand_core`.
Cargo در اولین build وابستگی‌های لازم را دریافت و Cargo.lock موجود پروژه را به‌روز می‌کند.
Cargo.lock در این محیط دوباره تولید نشده است؛ اولین build را با `--locked` اجرا نکنید و lockfile به‌روزشده را commit کنید.
دریافت وابستگی‌ها فقط برای ساخت روی سیستم توسعه است؛ بررسی رمز در برنامه نصب‌شده آفلاین انجام می‌شود.

تست‌های Rust، روی سیستم توسعه‌ای که پیش‌نیازهای Tauri را دارد:

```powershell
cargo test --manifest-path .\src-tauri\Cargo.toml --lib
```

تست‌های Rust از verifier آزمایشی ثابت در `src-tauri/tests/fixtures` استفاده می‌کنند؛
بنابراین تغییر رمز واقعی، تست‌ها را وابسته به آن رمز نمی‌کند.

### چک‌لیست دستی

۱. بدون رمز، جدول مدیریت نمایش داده نشود.
۲. رمز اشتباه جدول را باز نکند؛ `1111` آن را باز کند.
۳. قیمت یک برند را تغییر دهید؛ جدول پیش‌فاکتور همان محاسبات قبلی را انجام دهد.
۴. پنجره را بلافاصله بعد از تغییر قیمت ببندید و دوباره باز کنید: رمز دوباره خواسته شود و قیمت حفظ شده باشد.
۵. بدون ورود مدیر، توقف، ظرفیت، ریل و مشخصات مشتری را تغییر دهید و برنامه را دوباره باز کنید.
۶. بازنشانی نمونه ابتدا رمز بخواهد؛ سپس همان سؤال تأیید و فایل پشتیبان قبلی را اجرا کند.
۷. پنج رمز غلط وارد کنید و بسته‌بودن ورود برای یک دقیقه را بررسی کنید.
۸. هنگام بررسی رمز، پنجره را ببندید؛ نتیجه دیررس نباید جدول را دوباره باز کند.
۹. PDF قبل و بعد برای تنظیمات و قیمت یکسان، مبلغ‌ها و اقلام یکسان داشته باشد.

## محدوده بررسی انجام‌شده

- محتوای ۶ فایل موجود که patch تغییر می‌دهد، با blob SHA نسخه مبنا از GitHub تطبیق داده شد.
- ۲۷ تست واحدِ تنظیم رمز، نشست، IPC، صف ذخیره و lifecycle ورود اجرا و موفق شد.
- تست hook با یک harness قطعی و IPC شبیه‌سازی‌شده اجرا شده؛ جای تست React/WebView واقعی نیست.
- سرویس‌های جدید احراز هویت، با TypeScript strict و اعلان حداقلی رابط Tauri بررسی شدند.
- JSX جدید از نظر syntax بررسی شد، نه build کامل Next.js.
- ۹ تست native برای رمز، محدودیت تلاش، policy و تراکنش SQLite نوشته شده؛ در این محیط اجرا نشده‌اند.
- Rust/Cargo و وابستگی‌های کامل برنامه در محیط بررسی موجود نبودند؛ build ویندوز، اجرای WebView و
  کل مجموعه تست محاسباتِ آخرین ریپو در اینجا تأیید نشده‌اند.
- تغییرات به همان فایل‌های ذکرشده و فایل‌های جدید امنیتی/تست/راهنما محدود است؛ داده و فرمول دست نخورده است.

## نکات ممیزی که عمداً خارج از این patch ماندند

برای جلوگیری از تغییر رفتار برنامه سالم، بازطراحی گسترده انجام نشد.
رمزگذاری SQLite، تغییر سیاست CSP، حساب‌های چندکاربره، امضای نصب‌کننده و همگام‌سازی دستگاه‌ها
به پروژه جداگانه و تست مستقل نیاز دارند. این patch ادعای حل آن‌ها را ندارد.
